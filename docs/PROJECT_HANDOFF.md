# Living World 项目交接文档

更新时间：2026-07-24

## 一句话定位

这是一个“会生活、可以进入、也可以回看”的小世界：居民持续行动，玩家以 MUD 角色视角介入世界，并可以切换到历史视角查看角色的完整人生轨迹。

## 当前产品方向

项目不再以资源管理面板为核心。数字只作为世界状态的后台反馈，主要体验应该是：

```text
进入一个地点 → 观察和行动 → 遇到人物/危险 → 做出选择 → 世界留下后果 → 事后回看历史
```

三个互相连接的视角：

1. 角色视角：玩家只能看到角色当下所在地点、听见的内容和可执行动作。
2. 冒险视角：进入森林、废墟等区域，进行探索、解谜、遭遇和多路线处理。
3. 历史视角：查看某个角色完整的时序历史，包括角色当时不知道的事实。

## 当前已经实现

### MUD 角色视角

- 当前地点、地点描述和出口
- 行动记录日志
- 命令输入框
- 快捷动作：观察、交谈、跟随、寻找线索
- 可切换查看附近居民
- 居民有地点、状态、职业和性格

当前可识别的命令示例：

```text
观察
去森林
和阿岚交谈
跟随阿岚
寻找线索
```

### 冒险竖切片

入口在顶部“冒险”视角，当前流程是：

```text
森林边缘 → 旧哨站 → 灰鳞兽遭遇
```

可选方式：

- 观察灰鳞兽，发现它受伤并在保护幼崽
- 举火把驱赶
- 投喂干粮和平解决
- 直接战斗并承担受伤风险
- 撤退
- 调查树根寻找隐藏线索

冒险有体力、补给、线索和结果日志，但目前还没有把结果真正写回持久的世界状态。

### 历史视角

- 可以按人物查看编年史
- 时间线包含关键事件
- 部分事件标记为“角色当时并不知道”
- 当前已经展示阿岚和小满的部分历史

## 当前已知问题

### 居民暂时只有 4 人

当前 `app/page.tsx` 里的 `agents` 数组只有：

- 阿岚
- 小满
- 石头
- 月芽

这是为了快速做 MUD/冒险竖切片而进行的临时简化，不是最终设定。后续应恢复为完整 8 人，并让 8 人都拥有独立的技能、性格、关系和历史。

### 冒险结果还没有回流到世界

现在“回到聚落”只是返回角色视角。下一步应该让结果影响：

- 聚落资源
- 居民伤势和关系
- 新地点是否解锁
- 历史时间线
- 后续事件和任务

### 世界事件目前主要是静态数据

下一步应该把静态叙事升级为事件流：每个行动写入统一事件记录，再分别投影为角色视角和历史视角。

建议的数据形态：

```ts
type WorldEvent = {
  turn: number;
  actor: string;
  location: string;
  action: string;
  facts: string[];
  visibleTo: string[];
  consequences: string[];
};
```

## 下一阶段建议顺序

### 第一优先级：恢复 8 人

为所有居民补齐：

- 职业和特长
- 性格倾向
- 初始地点
- 与其他居民的关系
- 个人历史
- 冒险中的独特解法

### 第二优先级：让冒险影响生活世界

例如：

- 投喂灰鳞兽：森林路线变安全，但消耗聚落补给
- 直接战斗：获得通道，但同行居民受伤
- 撤退：保留体力，灰鳞兽之后可能改变位置
- 发现徽记：解锁旧哨站地下蓄水室

### 第三优先级：统一事件流

不要分别维护“角色日志”和“历史日志”。所有事情先写入世界事件流，再根据观察范围生成不同视角：

```text
真实事件流
  ├─ 角色视角：只显示当前角色能感知的部分
  └─ 历史视角：显示完整事实和隐藏后果
```

### 第四优先级：增加任务链

建议先完成一条任务链：

```text
河水退去
  → 去森林找铜管
  → 进入旧哨站
  → 处理灰鳞兽
  → 找到地下蓄水室
  → 决定是否启动旧时代设备
  → 改变聚落未来
```

## 本地运行

在项目根目录执行：

```bash
npm install
npm run dev
```

访问：

```text
http://localhost:3000
```

构建验证：

```bash
npm run build
```

当前 `npm run build` 可以通过。仓库原有的 `tests/rendered-html.test.mjs` 针对旧的预览骨架，依赖已经不存在的 `app/_sites-preview/SkeletonPreview.tsx` 和旧 meta 标记，因此测试失败属于过时测试，不是当前页面构建错误。

## 设计判断

不要回到“更多按钮 + 更多数字”的方向。新增系统前先问：

1. 玩家是否做了一个明确的选择？
2. 选择是否改变了一个人物、地点或未来事件？
3. 玩家能否在叙事中感受到后果？
4. 过一段时间后，历史视角能否解释这个后果是如何形成的？

如果答案是否定的，这个系统大概率只是装饰，而不是玩法。
