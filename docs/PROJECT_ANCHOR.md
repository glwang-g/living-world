# ComputerScienceWorld：项目锚点

## 我们到底在做什么

我们要做的不是“有居民的 Minecraft”，也不是“带地图的 MUD”，而是一个逐渐变得可理解、可修改、可编程的世界。

玩家先进入世界，理解世界的规则；然后建造机制，改变规则的运行方式；最后把重复行动交给居民或代码。

## 三个阶段

### 1. 物理世界

- 方块空间
- 移动、破坏、拾取、放置
- 昼夜、危险、资源
- 玩家可以看见自己的修改

### 2. 机制世界

- 火把、导线、门、压力板、水流
- 信号和状态转换
- 机关、自动化和基地系统
- 玩家开始设计系统，而不是只操作系统

### 3. 代理世界

- 居民拥有目标、记忆和策略
- 代理读取世界状态
- 玩家可以分配任务或编写行为
- 历史视角记录世界如何被玩家和代理共同改变

## 体验检查

一个合格的功能应该让玩家产生至少一种感觉：

- “我发现了一条规则。”
- “我可以用不同方式解决它。”
- “我建的东西真的改变了世界。”
- “这个世界在我不注意时也会继续运行。”
- “我想回头看看它是怎么变成现在这样的。”

如果功能只让玩家等待、领取、升级或查看数字，它大概率不属于核心路线。

## 当前决策

保留当前方块世界作为 MVP 地基；暂缓大规模居民、复杂剧情和数值成长，直到世界的空间操作、规则和自动化变得有趣。

### 下一步推荐

1. 让火把有照明范围，让夜晚真正影响可见性。
2. 增加简单信号：开关 → 导线 → 门。
3. 增加可被信号触发的机关。
4. 记录统一事件流，并为角色视角/历史视角提供不同投影。
5. 让一个简单居民读取机关和资源状态，执行采集或回家行为。
