## 2026-07-31：世界时间采用 20 分钟日循环

- `world-server` 每 50 秒推进一个世界小时；完整 24 小时即现实 20 分钟，采用 Minecraft 早期的一天节奏。
- 浏览器仍每秒请求快照；它只是在同一个世界小时内看到稳定的世界状态，不再每秒跳过一小时。
- 旧的已运行 `world-server` 不会自动获得这个刻度，修改后需要重启服务。
- 世界从第 1 天 `05:00` 起步，因此首次进入就是白天；夜晚、怪物和事件流仍由服务端统一裁决。

## 2026-07-31：从点击操作走向角色意图与可观察世界

### 操作语义

- `E` 是挖掘模式：点击天然树木、石头、泥土或火把，角色会自动寻路到目标旁并执行挖掘。
- `F` 是自由模式：点击目标只移动，不附带挖掘或放置。
- 按住 `Shift` 点击可放置位置，会覆盖当前模式，形成“移动并放置”的连续意图。
- 远处行动按路径逐格执行；逻辑位置每步更新，角色视觉位置在格子之间平滑过渡，并播放轻微行走起伏。
- 玩家现在有上、下、左、右四向角色素材和朝向状态；朝向来自真实移动方向，不再使用临时箭头标记。

### 资源与结构

自然资源和玩家建造物已经在协议、服务端和前端分离：

| 类型 | 世界语义 | E 挖掘模式 |
| --- | --- | --- |
| 天然石头、树木、天然泥土 | 可采集资源 | 可以挖掘 |
| 木墙、石墙、放置泥土 | 玩家建造结构 | 不可挖掘 |

- 石墙使用独立的 `stone-wall` 类型，视觉为横向红砖纹理。
- 木墙使用横向木板纹理。
- 放置泥土使用独立的 `placed-dirt` 类型，与天然泥土的自然土 mound 纹理区分。
- 结构拆除尚未开放，后续应设计独立的 `Dismantle` 意图，不复用资源挖掘。

### 怪物、视线与火把

- 夜间怪物只有在视线未被树木、石头、泥土或墙体阻断时，才会主动追近玩家。
- 玩家移动到怪物相邻位置，或怪物主动移动到玩家相邻位置，都会触发攻击和伤害事件。
- 已点燃/放置的火把会使怪物停止追击并被驱离。
- 怪物移动、被驱赶、玩家受伤都会写入世界事件流。
- 新增 Rust 测试覆盖怪物追近、相邻攻击、障碍遮挡、火把驱赶，以及资源/结构类型区分。

### 探索记忆

- 当前视野内的方块正常显示。
- 曾经观察过但目前不可见的方块保留原类型，并以半透明方式显示。
- 从未观察过的区域仍显示为未知。
- 探索记忆按绝对世界坐标保存，不会因镜头平移而丢失。

### 新增视觉资产

- `public/player-explorer-directions-source.png`：绿幕处理前的源图，仅作为资产源文件保留。

## 2026-07-29：ComputerScienceWorld 方块世界 MVP 增量

### 当前方向

项目已经从早期的居民聚落/MUD 竖切片，转向 ComputerScienceWorld：

```text
理解世界规则 → 在方块世界中行动 → 建造安全与机制 → 逐步走向自动化和代理
```

当前优先保证方块世界的空间感、规则反馈和可玩性，不急着扩展复杂居民、剧情或成长数值。

### 世界与服务端

- 世界从固定 20×12 改为坐标生成的无限世界。
- 20×12 仍作为初始区域生成样式，不再是世界边界。
- Rust `world-core` 持有权威世界状态，React 只负责显示和发送命令。
- 世界快照会保存玩家、背包、怪物、昼夜状态和玩家修改过的坐标。
- `world-server` 持续 tick、持久化快照，并追加 `world.events.log`。
- 服务端仍监听 `127.0.0.1:8787`。

### 2026-07-29 增量：规则闭环与操作语义统一

本轮围绕“玩家能否理解并验证世界规则”推进了三项核心修正。

#### 1. 统一 E/Q 操作入口

- 地图上方不再展示“挖掘/放置”按钮，避免与键盘操作形成两套语义。
- `E` 进入挖掘，`Q` 进入放置，方向键和 `WASD` 继续负责移动。
- 新手教学、左侧操作卡片和地图底部提示统一使用这套说法。
- `C` 仍用于显示/隐藏光标的世界坐标。

#### 2. 统一前后端放置规则

- 前端和 Rust 服务端现在都允许在草地或泥土上放置方块。
- 服务器仍是规则权威，客户端的点击校验只是即时反馈。
- 新增测试覆盖“泥土上可以放置火把”的行为，避免离线和在线模式产生不同结果。

#### 3. 封闭避难所、火把与怪物形成最小互动闭环

- 服务器通过局部洪水填充判断玩家所在区域是否被木墙/石墙封闭。
- 封闭区域会被标记为 `sheltered`，前端目标提示会显示当前是否处于安全避难所。
- 火把保持 4 格、受墙体视线影响的照明范围；玩家被火把照亮时，夜间怪物不会造成伤害。
- 夜间怪物靠近时，只有在玩家既未被火把照亮、又不在封闭避难所内时才会扣血。
- 服务器观察快照新增 `sheltered` 和 `torch_lit` 字段，让界面展示真实规则状态，而不是根据“放置数量”猜测安全性。
- 新增封闭墙体保护、火把驱避怪物两组 Rust 行为测试。

### 观察与视野

- 浏览器接收以玩家为中心、根据屏幕空间动态计算的矩形局部观察窗口；每个方格保持正方形。
- 白天默认观察半径为 6，夜晚缩短到 3。
- 火把可在一定范围内照亮区域。
- 墙体会阻断视线。
- 未看见的格子显示为 `unknown`，可通过声音提示远处怪物或黑暗逼近。
- 前端已经区分“服务端观察原点”和“客户端镜头原点”：
  - 玩家在地图窗口内移动时，地图不动；
  - 玩家接近窗口边缘后，镜头才整体平移；
  - 已观察到的格子会尽量保留。

### 移动与碰撞规则

当前只有以下方块可站立/穿越：

- 草地
- 火把

以下方块会阻挡移动：

- 树木
- 石头
- 泥土
- 木墙/石墙
- 水面

树木需要先挖出木材，再用木材放置木墙；木墙和石墙才能组成避难所。火把可以穿过，但不是武器，主要用于照明和保护范围。

### 交互反馈

- 穿越障碍、距离太远、挖掘失败、放置失败时，会显示地图中央的浮动提示框。
- 浮动提示约 2.2 秒后消失，不再把徒劳操作写进世界历史日志。
- 提示框使用鲜明橙金色边框和发光效果。
- 新手教学打开时会把页面滚到最顶部，并进行边缘高亮闪动。
- 左侧“再看一遍教学”在教学已打开时不会关闭教学，而是重新跳转顶部并重新播放高亮。
- 顶部“新手说明”和教学框内“关闭 ×”仍然可以正常开关教学。

### 接手时的注意事项

1. 如果修改了 Rust 服务端规则，需要重启已经运行的 `world-server`，否则浏览器仍会连接旧进程。
2. 不要把前端本地状态重新发展成世界权威状态；服务端规则优先。
3. 新增方块时同时考虑：生成、碰撞、视线、挖掘、放置、图标、提示和测试。
4. 继续保持“玩家先发现规则，再利用规则建造系统”的路线。
5. 当前工作区仍有未提交的实现改动，不要用清理命令覆盖它们。
