## 2026-07-29：ComputerScienceWorld 方块世界 MVP 增量

### 当前方向

项目已经从早期的居民聚落/MUD 竖切片，转向 ComputerScienceWorld：

```text
理解世界规则 → 在方块世界中行动 → 建造安全与机制 → 逐步走向自动化和代理
```

当前优先保证方块世界的空间感、规则反馈和可玩性，不急着扩展复杂居民、剧情或成长数值。

### 世界与服务端

- 世界从固定 20×12 改为坐标生成的无限世界。
- 20×12 仍作为初始区域生成样式，不再是世界边界。
- Rust `world-core` 持有权威世界状态，React 只负责显示和发送命令。
- 世界快照会保存玩家、背包、怪物、昼夜状态和玩家修改过的坐标。
- `world-server` 持续 tick、持久化快照，并追加 `world.events.log`。
- 服务端仍监听 `127.0.0.1:8787`。

### 观察与视野

- 浏览器接收以玩家为中心的 13×13 局部观察窗口。
- 白天默认观察半径为 6，夜晚缩短到 3。
- 火把可在一定范围内照亮区域。
- 墙体会阻断视线。
- 未看见的格子显示为 `unknown`，可通过声音提示远处怪物或黑暗逼近。
- 前端已经区分“服务端观察原点”和“客户端镜头原点”：
  - 玩家在地图窗口内移动时，地图不动；
  - 玩家接近窗口边缘后，镜头才整体平移；
  - 已观察到的格子会尽量保留。

### 移动与碰撞规则

当前只有以下方块可站立/穿越：

- 草地
- 火把

以下方块会阻挡移动：

- 树木
- 石头
- 泥土
- 木墙/石墙
- 水面

树木需要先挖出木材，再用木材放置木墙；木墙和石墙才能组成避难所。火把可以穿过，但不是武器，主要用于照明和保护范围。

### 交互反馈

- 穿越障碍、距离太远、挖掘失败、放置失败时，会显示地图中央的浮动提示框。
- 浮动提示约 2.2 秒后消失，不再把徒劳操作写进世界历史日志。
- 提示框使用鲜明橙金色边框和发光效果。
- 新手教学打开时会把页面滚到最顶部，并进行边缘高亮闪动。
- 左侧“再看一遍教学”在教学已打开时不会关闭教学，而是重新跳转顶部并重新播放高亮。
- 顶部“新手说明”和教学框内“关闭 ×”仍然可以正常开关教学。

### 关键代码位置

- `engine/crates/world-core/src/lib.rs`：无限世界、观察、碰撞、昼夜和资源规则。
- `engine/crates/world-protocol/src/lib.rs`：`Observation`、`WorldSnapshot`、方块和命令 DTO。
- `engine/crates/world-server/src/main.rs`：HTTP 快照、命令入口、持久化和事件流。
- `app/page.tsx`：前端同步、镜头原点、输入、提示、教学和方块渲染。
- `app/globals.css`：13×13 方格、材质、角色/方块资产、浮框和教学高亮。

### 验证结果


Rust 当前包含 7 个 `world-core` 测试，覆盖确定性、昼夜、无限移动、快照恢复、夜间视野、火把照明和碰撞规则。

### 接手时的注意事项

1. 如果修改了 Rust 服务端规则，需要重启已经运行的 `world-server`，否则浏览器仍会连接旧进程。
2. 不要把前端本地状态重新发展成世界权威状态；服务端规则优先。
3. 新增方块时同时考虑：生成、碰撞、视线、挖掘、放置、图标、提示和测试。
4. 继续保持“玩家先发现规则，再利用规则建造系统”的路线。
5. 当前工作区仍有未提交的实现改动，不要用清理命令覆盖它们。

## 后续候选方向

这些不是本次已实现内容，后续按体验优先级推进：

1. 让火把与怪物互动更明确：照明范围、驱避距离、生命周期。
2. 增加门、开关、导线等最小信号系统。
3. 让避难所被系统识别，并在夜晚给出可理解的安全反馈。
4. 让一个简单居民读取世界状态，执行采集、回家或点火把行为。
5. 继续保留世界事件流，为未来历史视角和代理行为提供基础。
